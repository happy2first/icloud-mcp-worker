# DAV 服务发现修复（2026-10-13）

用户报告保存 App 专用密码后，服务检查分别返回资源校验错误和连接失败。没有生产日志访问权限，不能仅凭请求编号确认实际 Apple 响应。

## 已复现并修复

- `fast-xml-parser` 开启属性解析后，`<href xmlns="DAV:">...</href>` 返回带 `#text` 的对象。此前响应资源 href 被 `String()` 转成 `[object Object]`；principal/home href 对象进入 `new URL()`，产生错误地址。现在显式提取并校验文本，统一处理带属性及无属性 href，并去掉地址前后空白。
- DAV 服务白名单此前拒绝中国区地址。现在仅增加各自的 `caldav` / `contacts` 及 `pNNN-*` 的 `.icloud.com.cn` HTTPS 主机，仍拒绝跨服务、非标准端口、查询参数、片段和 URL 凭证。
- 发现入口因认证拒绝、权限拒绝或连接失败时，最多尝试一次固定同服务中国区入口；没有写操作重试，不针对限流或协议错误回退。全部发现网络请求共享 40 秒预算，每段请求仍为 10 秒。
- 发现记录不再假定第一条就是 principal/home，按所需属性选择。重定向缺失地址、循环和次数超限分别返回明确错误。
- HTTP 失败、网络失败及预算超限现在有独立 DAV 详情；管理页显示这类由服务端生成的详情，不包含账户、密码、资源路径或上游响应体。

## 回归验证

新增 `tests/dav-discovery.test.ts`：日历和通讯录完整发现链、默认命名空间及带属性 href、地区重定向、显式 443、相对资源路径、区域入口单次回退、恶意地址拒绝、错误分类及敏感内容不外泄。

此改动不修改数据库、已有凭证或服务开关。测试使用模拟 Apple 响应，真实账户仍需部署后分别点击日历、通讯录的“检查”验收。若仍失败，管理页会显示请求方法及失败类型，便于继续定位。

参考：中国区 DAV 入口的维护者说明：<https://github.com/bitfireAT/davx5-ose/discussions/225>；DAV href 为 URI 的标准定义：<https://www.rfc-editor.org/rfc/rfc4918#section-14.7>。
